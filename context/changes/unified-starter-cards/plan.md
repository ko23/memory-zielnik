# Unified Starter Cards Implementation Plan

## Overview

Restructure the starter-herb seed data so starter cards become real, editable/deletable `HerbCard` records — indistinguishable from user-added cards once seeded — without a required `sourceLabel` (attribution) or any approval step. Starters keep skipping approval (already true today); the change is about making them first-class, mutable deck entries instead of a fixed, separately-tracked layer.

## Current State Analysis

`src/lib/storage/types.ts` defines `HerbCard` with `sourceLabel: string` as required. `index.ts`'s `createCard(input: {name, imageDataUrl, sourceLabel})` requires all three fields. `seed-data.ts` (generated by `scripts/generate-herb-seed-data.mjs`) holds 14 entries shaped `{name, imageDataUrl, sourceLabel: "Wikipedia (GFDL)"}`. `seed.ts`'s `seedDefaultCards()` already calls `createCard()` per entry only when the deck is empty — starters already become normal, editable/deletable `HerbCard` records today; the only things this plan changes are the seed data's shape and `sourceLabel`'s requiredness. `herb-card-authoring/plan.md` (Phase 1 committed, Phases 2-4 not yet built) contains a stale line asserting no changes will be made to `seed-data.ts`/`seed.ts`/`F-01`'s contracts.

## Desired End State

`HerbCard.sourceLabel` is optional; `createCard`'s input accepts an optional `sourceLabel`. `seed-data.ts`'s entries are shaped `{name, path, imageDataUrl}` — `path` is the source file's location under `assets/herb-seed-sources/` (for traceability/regeneration only, never persisted onto a `HerbCard`), `imageDataUrl` is the same base64 data URL as before. `seed.ts` seeds cards from this shape with no `sourceLabel`. `herb-card-authoring/plan.md`'s stale boundary line is corrected. Verification: `npm run test` passes (existing + extended assertions); `npm run build` succeeds; running the generator reproduces the new-shaped `seed-data.ts`.

### Key Discoveries:

- `path` never needs to reach the persisted `HerbCard` — once `createCard` runs, a starter card has the exact same shape as a user card (id, name, `imageDataUrl`, optional `sourceLabel`, timestamps). This is what makes "editable/deletable the same way" true without any special-casing in `index.ts`.
- No live migration concern: nothing has ever called `seedDefaultCards()` from a page (that's `herb-card-authoring` Phase 2, not yet built), so there's no deployed data in the old shape to migrate.
- `updateCard`'s patch type (`Partial<Pick<HerbCard, "name" | "imageDataUrl" | "sourceLabel">>`) already makes every patch field optional regardless of `HerbCard`'s own field requiredness — no change needed there.

## What We're NOT Doing

- Not adding `path` (or any new field) to the persisted `HerbCard` type — it stays seed-file-only metadata.
- Not building any UI yet — `herb-card-authoring`'s Phases 2-4 (not yet implemented) are where a starter card without a `sourceLabel` actually gets rendered; this plan only ensures the data layer supports that correctly, per this session's "show nothing" decision for the future UI.
- Not resolving the image-lookup-vs-upload question for newly-added herbs — untouched, separate topic.
- Not adding a `sourceLabel` placeholder string anywhere — per this session's decision, absence is absence, not a forced default.

## Implementation Approach

Widen `HerbCard`/`createCard`'s contract to make `sourceLabel` genuinely optional, reshape the seed generator's output to `{name, path, imageDataUrl}`, and update `seed.ts` to map the new shape into `createCard` calls (no `sourceLabel` passed for starters). Then correct `herb-card-authoring/plan.md`'s now-inaccurate claim that this area wouldn't change.

## Phase 1: Data model + seed restructuring

### Overview

The actual code change: optional `sourceLabel`, new seed-data shape, updated seeding, extended tests.

### Changes Required:

#### 1. Optional `sourceLabel`

**File**: `src/lib/storage/types.ts`

**Intent**: A `HerbCard` no longer requires an attribution label — starter cards won't have one.

**Contract**: `sourceLabel?: string` (was `sourceLabel: string`).

#### 2. `createCard` accepts optional `sourceLabel`

**File**: `src/lib/storage/index.ts`

**Intent**: Match the widened `HerbCard` contract at the one place that constructs new cards.

**Contract**: `createCard(input: {name: string; imageDataUrl: string; sourceLabel?: string})`. The constructed `HerbCard`'s `sourceLabel` is `input.sourceLabel` (`undefined` when omitted — not coerced to an empty string).

#### 3. Seed-data shape + generator

**File**: `src/lib/storage/seed-data.ts` (generated), `scripts/generate-herb-seed-data.mjs`

**Intent**: Replace the Wikipedia-attribution field with a traceability pointer back to the source image, since starters no longer carry per-card attribution.

**Contract**: `HerbSeedCard` becomes `{name: string; path: string; imageDataUrl: string}`. The generator emits `path` as the source file's path relative to the repo root (e.g. `"assets/herb-seed-sources/koper-wloski.jpg"`) instead of the current hardcoded `sourceLabel: "Wikipedia (GFDL)"` line; `imageDataUrl` and the resize/compression settings (480px wide, JPEG q75) are unchanged. Re-run the generator once to produce the actual committed file.

#### 4. Seeding uses the new shape

**File**: `src/lib/storage/seed.ts`

**Intent**: Feed the reshaped seed entries into `createCard` correctly — no `sourceLabel` passed.

**Contract**: `createCard({name: seedCard.name, imageDataUrl: seedCard.imageDataUrl})` per entry (`seedCard.path` is not passed to `createCard` — it has no home on `HerbCard`).

#### 5. Extended tests

**File**: `src/lib/storage/seed.test.ts`

**Intent**: Prove the new shape actually flows through correctly.

**Contract**: Extend the existing "populates all 14 seed cards" test to also assert every seeded card's `imageDataUrl` is a non-empty string and `sourceLabel` is `undefined`. Add a small assertion (or a new test) that every `HERB_SEED_CARDS` entry has a `path` field pointing under `assets/herb-seed-sources/`.

### Success Criteria:

#### Automated Verification:

- Generator runs cleanly: `node scripts/generate-herb-seed-data.mjs`
- Tests pass: `npm run test`
- Type checking passes: `npx tsc --noEmit`
- Build still succeeds: `npm run build`

#### Manual Verification:

- None — this phase's behavior is fully covered by automated tests; there's still no UI wired to any of this.
